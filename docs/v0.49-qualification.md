implementation conversation. The [machine-readable profile](../plans/v0.49-qualification-profile.json)
is the input to qualification; its checksum is recorded in each observation.
These thresholds are prospective acceptance limits, not achieved capacity.

The original producer pin reported `permission denied for table pgt_dependencies`
after restoring pending work. Producer commit `c7e257e5` separates query parsing
under the stream owner from privileged CDC metadata lookup during delta SQL
generation. The candidate pins that merged repair; the original-pin compatibility
lane and failure evidence remain unchanged. Runtime SELECT on the producer-private
catalog remains denied, and healthy later managed cycles are mandatory.

Retain coherent backups and their matching binaries across the retention horizon.
No pruning is enabled. Retry/audit evidence must remain available with the
request and receipt it explains. The existing small-fixture recovery measurements
do not establish these workload-scale limits or 90-day recovery coverage.

The frozen S1 workload and its original failure evidence stay intact. A measured
45 to less than 60/minute result can satisfy only the throughput floor, and only
when throughput is the sole raw failure, the raw exit remains 1, all 300 admissions
and 1,200 source rows have complete case/receipt vectors, zero future receipts
exist, and every other gate and the paired control pass. Upstream's separately
approved acceptance policy cannot replace this repository's 45/minute floor.

The full lane exercises populated adjacent `0.46.0` -> `0.46.1` upgrade and an
injected end-of-DDL failure before the successful upgrade. It compares the entire
core/adapter table population, public MDM cases/receipts, predecessor extension
version and complete public callable definitions/privileges after rollback.
The fixture populates an ordinary decision program and, when MDM is present,
an adapter policy package. Core-only and adapter-present variants must both pass.
It does not establish a populated temporal upgrade: the historical `--maintenance`
lane currently stops because the `0.46.0` predecessor rejects the installed
`0.108.3` producer before temporal authoring. Its original failure is retained;
the actual predecessor producer must be used to qualify that joint upgrade path.

The pending lane deliberately queues two real MDM occurrences through the public
evaluation API, then completes one through the restricted runtime. The other
episode remains pending when the active database is copied and the paused
database is physically backed up. Both copies start with managed effects
disabled. Before activation, copied case, source, completed/pending work,
request, attempt and receipt vectors must match exactly and authorized adapter
candidates must be empty. After explicit entity-role reconciliation, the old
receipt must replay identically and only the remaining episode may complete.
The physical restore restarts the real background worker; the template clone
uses explicit public managed cycles. New canonical request keys/digests, full
requests/receipts, controls and attempts are checked, and later cycles must leave
all durable vectors unchanged. The source database must remain unchanged.

This pending-work drill is not a logical `pg_dump`/`pg_restore` proof or a
workload-scale recovery qualification. Its deliberate setup evaluation does not
replace the separate real idle-time and outage tests.

Each run retains raw logs, failures, image ID, dependency labels, installed
versions/capabilities, callable inventory, source and profile checksums and exact
durable vectors. `QUALIFICATION_INCOMPLETE` means focused assertions passed but
release gates remain open. A focused recovery/outage decision or a zero process
exit cannot establish complete release acceptance.

## Operator procedure

Use the existing [adapter setup](../integrations/pg-mdm/README.md) and
[temporal/occurrence contract](../contracts/MDM-STEWARDSHIP-1-escalation-v049.md).
Install with the installer identity; author and review rules through the existing
authoring flow. The ordinary deadline entry point is
`pgreact_api.author_deadline_rule(name, candidate, key_column, deadline_column,
consequence_kind, callback)`. The candidate must preserve the MDM occurrence and
original `due_at`; equality with the one database-time evaluation sample is due.
Time samples, publication timestamps and heartbeats never salt request keys.

The entity execution role explicitly creates the level-2 binding and authorizes
its actions. Use a `NOSUPERUSER`, `NOBYPASSRLS` runtime login with only the
configured worker membership. Keep author-owned refresh/dispatch privileges;
granting runtime SELECT on business sources or human approval APIs is unnecessary.
Do not grant the runtime the public `run()` setup API. The managed worker uses
its existing internal evaluation path.

Set `pg_react.poll_interval_ms=1000`, `pg_react.batch_size=32`, the intended
database list and restricted runtime login. The database list and login require a
PostgreSQL restart. Only activate the database after reviewing the exact artifacts,
capabilities, grants and binding; installation/upgrade never authorizes activation.
For the 0.14.2 MDM candidate, preload `pg_mdm` alongside `pg_trickle` and
`pg_react`. Every PostgreSQL restart invalidates policy activation: the entity
execution role must recheck and reconcile each enabled binding before resuming.
Reconciliation rejects a binding whose retained MDM policy, limits, entity or
worker role no longer matches the adapter configuration.
The managed cycle blocks all jobs in that database while an enabled binding
requires reconciliation; pending work retains its original deadline.

Inspect through existing public surfaces, subject to their configured grants:

```sql
SELECT pgreact_api.managed_status();
SELECT pgreact_api.deadline_history('your-deadline-rule');
SELECT pgreact_api.temporal_status();
SELECT * FROM pgreact.work;
SELECT * FROM pgreact.attempts;
SELECT * FROM pgreact_mdm.delivery_inspection_v1;
```

Use delivery inspection to correlate the original/requested deadline, requested
and applied level, pending/protected state, binding/policy version and terminal
receipt. `APPLIED_CONTROL` means a directive was delivered. Human review,
publication and business closure remain separate; automation cannot record the
human decision. A rejected or stale outcome requires the existing explicit
reevaluation/correction path, not mutation of an attempted payload.

Before maintenance, pause the binding as its entity execution role using
`pgreact_mdm.pause_intent_binding(binding_id, expected_runtime_version)` and
retain the returned runtime version. Wait for the acknowledged barrier; inventory
pending/leased/retry work and retain a coherent whole-stack backup. Use the actual
runtime version from the approved operator workflow; a binding version is a
different concurrency token. Pause does not undo an already accepted directive.

Reconciliation can re-add a case to the selector and create a new React activation.
The resume audit requires exactly one `ESCALATION_LEVEL_ALREADY_APPLIED` denial
for the already-applied occurrence/level, with complete canonical request, receipt,
attempt and work vectors. Cases and sources remain unchanged; later managed cycles
and a cold restart must preserve the entire resulting durable state. The resume
fixture commits its operator checks atomically before managed evaluation begins.

Restore the entire coherent database with its matching binaries and receipts.
Start with `pg_react.databases=''` and the producer's automatic coordinator
disabled. A copied enabled flag, database OID or role OID is insufficient
activation authority. Recheck installed capabilities, roles, policy digest,
occurrence mappings, original deadlines, pending work and applied receipts before
allowing effects. Never restore React requests independently of MDM receipts.

For a template copy, recover the producer capture identity through its supported
`pgtrickle.recover_capture_instance()` API. Rebind restored MDM helpers through
the entity's `mdm_admin.rebind(entity_name)` procedure, then call
`pgreact_mdm.reconcile_intent_binding(binding_id, expected_runtime_version)` as
that entity execution role. Use the actual restored runtime token, including zero
only when the installed runtime contract reports a missing entry. Capture adoption
leaves copied producer streams suspended and marked for reinitialization. Review
their inventory and explicitly call `pgtrickle.resume_stream_table(qualified_name)`
for the approved streams before managed refresh; adoption alone does not resume
them. Verify exact
original-receipt replay before resuming the approved database and worker login.
Drain at most 32 claims per cycle without moving deadlines to recovery time or replaying
missed polls. Retain all attempted identities; a new intended action uses new work.

An upgrade failure must leave the predecessor intact. If coherent binary/runtime
recovery is needed, restore the whole recovery point and matching prior artifacts;
do not attempt a reverse extension migration. Logical restore and workload-scale
resumption remain unqualified until their required evidence is recorded.
If resumption reports the observed `pgt_dependencies` permission error, pause
again and verify that the qualified candidate producer and matching SQL are installed.
Do not grant producer-private catalog SELECT or switch to a superuser runtime.
