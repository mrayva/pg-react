# 0.46.1 core claim maintenance

This maintenance candidate corrects name resolution in the shared generic claim
sweep. Its OUT parameter `rule_version_id` collided with unqualified table
references, producing SQLSTATE 42702 before managed delivery. The correction
qualifies the table references in `pgreact.claim`; its wrappers, result type,
lease semantics and transactional execution path stay intact. The approved
role correction restores only the documented `managed_cycle()` EXECUTE grant
to the configured worker group and revokes it from the previous worker on rotation.
It uses the shared grant helper for configuration and populated upgrades.
The native
managed worker admits this exact SQL patch version; unapproved future patches
remain rejected.

Published 0.46.0 and older install/upgrade SQL remain frozen. The current assembly
uses the exact published 0.46.0 predecessor followed by `sql/current/claim.sql`
and `sql/current/worker-grants.sql`. The adjacent 0.46.0-to-0.46.1 migration
contains those same corrections. This also
preserves the coordinator locks and package-preview patch that differ from the
older 0.43.3-based assembly. Cargo and optional adapter labels remain 0.48.0;
the installed core SQL version is 0.46.1.

From the repository root:

```sh
rtk proxy bash bin/assemble-sql sql/pg_react--0.46.1.sql sql/current/assembly.txt
rtk proxy bash bin/assemble-sql sql/pg_react--0.46.0--0.46.1.sql sql/current/upgrade-0.46.0-to-0.46.1.txt
rtk proxy docker build -f tests/integrations/pg-mdm/Dockerfile.v0.48 -t pg-react:claim-maintenance .
rtk proxy python3 tests/integrations/pg-mdm/time/audit.py pg-react:claim-maintenance .p2p/tmp/claim-check --maintenance
```

Use a new output directory each time. The runner creates only owned disposable
containers, disables networking, mounts the checkout read-only and removes its
container/volumes after retaining full observations. No production migration is
performed by these commands.

Maintenance mode checks fresh direct claims and populated predecessor upgrades
with the adapter absent and present. It reproduces the predecessor's exact
42702 failure, compares all core/adapter-owned table rows and public MDM
case/receipt rows across the upgrade, and checks complete callable definitions,
owners, ACLs, result/security attributes. Across the predecessor upgrade only
the claim definition and expected configured-worker `managed_cycle()` grant may
differ. Fresh and upgraded core inventories
must match. The fixture also checks full returned claims, normal worker-role
access, invalid arguments, leased-work exclusion, actual expiry/reclaim, stale
token rejection, exact callback effects and unchanged source rows. Complete worker
privilege vectors and actual denied public calls cover normal non-worker roles
and the superseded worker after rotation; no PUBLIC or bypass grant is added.

The real S1 future-deadline fixture requires the managed worker to reach a
public MDM receipt without source edits or manual time/coordinator calls. A
service login must already have SET membership in the configured
`application_roles.worker`. The adapter uses `SET LOCAL ROLE` to that existing
worker only around `managed_cycle()`, preserves `session_user`, and restores the
login role after success; transaction rollback restores it on an error. Missing
membership fails closed before the managed call. The public receipt records the
configured worker as actor and the service login as session role; MDM retains its
superuser-operation rejection.

The approved refresh boundary keeps generated streams owned by their author and
grants `MAINTAIN` only to the configured worker. The grant is synchronized when
roles are configured, revoked from the previous worker on rotation, and applied
to newly created M0 streams. It adds no source-table `SELECT`, source-schema
`USAGE`, ownership transfer or new role membership. The bounded worker role
activation is separate and does not change the session login. This adapter change
depends on the separate pg_trickle refresh-only `MAINTAIN` capability;
the pinned 0.108.0 implementation still requires stream ownership. The local
upstream patch is not a released dependency, so S1 remains blocked until that
capability is released and the exact downstream fixture passes.
A successful feasibility run remains INPUT_BLOCKED until the separate S1
owner-confirmed fixtures, workload/resource measurements and signed numerical
operating envelope exist. Maintenance qualification does not enable production
escalation or clear S2/S3 by itself.

For an actual populated upgrade, follow the existing release-gates pause/barrier,
matching-binary backup, inventory, upgrade and explicit-resume procedure.
The tested SQL path is `ALTER EXTENSION pg_react UPDATE TO '0.46.1'`.
The migration changes the shared claim callable and documented worker grant;
it does not enable a policy,
rewrite deadlines or delete request/receipt/key history.
