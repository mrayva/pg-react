# v0.49 claimed-work barriers and terminal-pause resumption

This follows main `06c8fea9df0d997131709614a86b556c11c7bc42` (merged #26).
It fixes two actual defects, with separate failing-before evidence. It does not
change the approved workload/profile, receipt codecs, producer pin, default

The [evidence manifest](../tests/integrations/pg-mdm/evidence/v0.49-claimed-work/manifest.json)

## Confirmed defects

1. **MDM pause could acknowledge before an in-flight escalation committed.**
   The real React episode had claimed work, acquired its MDM binding lock and
   was waiting for the case row. An authorized pause committed first, then the
   blocked delivery applied `ESCALATE`. MDM's state transition did not take the
   binding lock. The shared MDM repair adds that lock and acquires the delivery
   binding lock before its separate eligibility read, so a pause-first wait
   cannot reuse the earlier runtime snapshot. Public signatures and frozen
   generated SQL bytes remain unchanged.
2. **React's retained terminal pause prevented fresh authorized work.**
   With MDM's barrier repaired, an attempted request correctly ended
   `BINDING_PAUSED`. After authorized reconciliation and genuine fresh React
   reevaluation, the old hold still blocked the new request at the same case
   revision. The adapter now treats that hold as terminal to its old request;
   a new work identity must still pass all current binding/candidate checks.
   It retains the old request, receipt, attempt and hold. Inspection keeps that
   paused attempt `HELD` while a fresh applied request reports no remediation.
   Other hold reasons and MDM's occurrence/level uniqueness remain enforced.

The currently pinned MDM artifact remains the original baseline; the shared MDM
repair [MDM PR #22](https://github.com/trickle-labs/pg-mdm/pull/22), source
`40e9cb7b9018627e2ecb17ca387017950d438c31`, is a separate candidate, not silently adopted as a release pin. The
linked preview workflow must qualify the exact repair source and inherited
libraries. Original pinned compatibility and historical failures remain intact.

## Executable matrix

Run `python3 tests/integrations/pg-mdm/time/audit.py IMAGE OUTPUT --claimed-work`.
Setup creates two real MDM cases through public authoring/publication APIs,
registers the adapter's native typed callback, and queues ordinary deadline work.
Every claim is through the public React API with `max_items=1`.

| Ordering | Required result |
| --- | --- |
| Claim/delivery holds binding, waits for case; operator pauses | Pause waits for delivery; acknowledgment cannot precede its control commit |
| Pause owns binding with uncommitted runtime change; delivery waits | After pause commits, immutable attempted delivery receives `BINDING_PAUSED`, not an old-snapshot control |
| Pause commits before React claims old queued work | Native callback rechecks eligibility; no MDM request or control; complete core terminal outcomes retained |
| Authorized resume and fresh reevaluation after terminal pause | A different work/request identity may apply its genuinely eligible next level; old paused bytes remain immutable |
| Claim precedes a human deadline edit; delivery waits on human case lock | Exact `STALE_CASE` / `FRESHNESS_TOKEN_MISMATCH` receipt with original canonical attempted request and current human controls |
| Human level change commits before claim | Previously queued work submits no MDM request and preserves human controls |
| Human lowers an already-applied level; new React generation | Exact `ACTION_DENIED` / `ESCALATION_LEVEL_ALREADY_APPLIED`; no repeat under the new key |
| Binding replacement lowers max level after one claim, before another | Both deliveries use current authorization and submit no control/request under old limits |

Synchronization observes `pg_blocking_pids` and transaction state, with finite
barrier, statement and subprocess deadlines. Poll intervals are not evidence of
success. Complete case/source, canonical request/receipt, attempt/work and hold
vectors are retained. Authorized reader diagnostics distinguish the old held
pause from the fresh application. Later restricted managed cycles must report
`ready` and leave durable vectors unchanged.

MDM's independent SQL test uses asynchronous dblink sessions against its public
pause API and the same binding-row barrier. It compares complete binding,
runtime, case and receipt state and joins the standard upstream packaged E2E
runner. dblink is a test-only PostgreSQL facility, not a runtime dependency.
